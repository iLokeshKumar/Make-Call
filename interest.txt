  Core Idea

  A model learns a mapping:

  input -> desired output

  For a text model:

  customer question -> correct support answer

  For ASR:

  audio waveform -> transcript

  For TTS:

  text + speaker identity -> speech waveform

  For voice cloning:

  text + reference voice embedding -> speech in that speaker’s style

  Fine-tuning means you start from a pretrained model and train it a little more on your specific data. You are not teaching it speech from zero;
  you are adapting it to your accent, domain vocabulary, microphone quality, language, speaker, or speaking style.

  Training From Scratch vs Fine-Tuning

  Training from scratch:

  - Needs huge datasets.
  - Needs many GPUs.
  - Costs a lot.
  - Usually only makes sense for research labs or platform companies.

  Fine-tuning:

  - Starts with a pretrained model.
  - Needs much less data.
  - Trains faster.
  - Is the practical route for most custom voice work.

  Adapters / LoRA:

  - Train only small extra layers.
  - Cheaper than full fine-tuning.
  - Lower risk of destroying the base model.
  - Common for LLMs and increasingly useful for audio models.

  Prompting / configuration:

  - Sometimes enough.
  - For voice agents, you may not need to train the audio model at all. You can customize behavior with prompts, tools, retrieval, and selected TTS
    voices.

  General Fine-Tuning Workflow

  1. Define the task clearly.

  Bad:

  I want a voice model.

  Better:

  I want an ASR model that transcribes Indian English sales calls with product names correctly.

  Or:

  I want a TTS model that speaks in my own recorded voice for narration.

  2. Collect data.

  For ASR:

  audio_file.wav + transcript.txt

  Example:

  {
    "audio": "calls/001.wav",
    "text": "Hello, this is Priya calling from Acme Insurance."
  }

  For TTS:

  clean sentence text + matching clean spoken audio

  Example manifest:

  {
    "audio": "speaker1/0001.wav",
    "text": "Welcome to the product walkthrough.",
    "speaker": "speaker1"
  }

  For classification:

  {
    "audio": "clip_001.wav",
    "label": "angry"
  }

  3. Clean the data.

  This is where most voice projects succeed or fail.

  For ASR:

  - Remove wrong transcripts.
  - Normalize punctuation consistently.
  - Keep domain terms exactly as you want them output.
  - Remove clips with multiple overlapping speakers unless your model supports that.
  - Split long recordings into smaller chunks, often 5-30 seconds.
  - Make sure audio and text align.

  For TTS:

  - Use quiet recordings.
  - Same microphone and room if possible.
  - Avoid background music, echo, clipping, breath blasts.
  - Record expressive but controlled speech.
  - Keep transcripts exact.
  - Remove bad takes.
  - Balance phonetic coverage: many sounds, sentence lengths, emotions, names, numbers.

  4. Split the data.

  Use separate sets:

  train: 80-90%
  validation: 5-10%
  test: 5-10%

  Never evaluate only on training data. That hides overfitting.

  5. Choose a base model.

  For ASR:

  - Whisper fine-tuning is common.
  - wav2vec2 / HuBERT / Conformer are also common.
  - Hugging Face has a full Whisper ASR fine-tuning walkthrough, including resampling audio, preparing labels, training with Trainer, and evaluating
    with WER. Source: Hugging Face ASR fine-tuning guide (https://huggingface.co/learn/audio-course/chapter5/fine-tuning).

  For TTS:

  - VITS, GlowTTS, XTTS, Piper, StyleTTS2, Bark-like models, NeMo TTS.
  - Coqui TTS docs show the standard training flow: choose model, configure dataset, load samples, initialize trainer, run training on GPU. Source:
    Coqui TTS training docs (https://docs.coqui.ai/en/latest/training_a_model.html).

  For voice cloning:

  - Prefer a multispeaker / speaker-embedding model.
  - Fine-tune only with voices you own or have explicit permission to use.
  - For many use cases, zero-shot voice cloning or speaker adaptation is enough; full fine-tuning is heavier.

  6. Preprocess audio.

  Typical settings:

  mono audio
  16 kHz for ASR, often Whisper/wav2vec2
  22.05 kHz / 24 kHz / 44.1 kHz for TTS depending on model
  consistent loudness
  trim leading/trailing silence
  remove corrupted samples

  For ASR, Hugging Face’s Whisper guide specifically resamples Common Voice audio from 48 kHz to 16 kHz and filters clips longer than 30 seconds
  before training.

  7. Train.

  Training means repeatedly showing the model batches of examples and updating weights to reduce error.

  Typical knobs:

  learning_rate
  batch_size
  epochs
  warmup_steps
  weight_decay
  gradient_accumulation
  checkpoint interval
  early stopping

  For small datasets, too many epochs can overfit fast. The model may sound good on training clips but fail on new text or new audio.

  8. Evaluate.

  For ASR:

  - WER: Word Error Rate.
  - CER: Character Error Rate.
  - Domain vocabulary accuracy.
  - Accent performance.
  - Noise robustness.
  - Latency.

  Hugging Face’s ASR guide uses WER as the main metric.

  For TTS:

  - Intelligibility: can listeners understand it?
  - Naturalness: does it sound human?
  - Speaker similarity: does it match the target speaker?
  - Prosody: rhythm, stress, pauses.
  - Stability: no skipped words, repeated words, strange artifacts.
  - Latency and generation speed.

  For voice agents:

  - Turn-taking latency.
  - Interruption handling.
  - Tool-call correctness.
  - Hallucination rate.
  - Transcript accuracy.
  - End-to-end user success.

  9. Iterate.

  A serious loop looks like this:

  baseline model
  -> eval failures
  -> inspect bad examples
  -> add/clean data
  -> fine-tune again
  -> compare metrics
  -> listen manually
  -> deploy small
  -> collect real failures
  -> repeat

  That eval loop is not optional. OpenAI’s optimization docs describe essentially this pattern: build evals, prompt, optionally fine-tune, evaluate
  on representative test data, adjust data/prompts, repeat.

  How Much Voice Data Do You Need?

  Rough practical ranges:

  For ASR domain adaptation:

  1-5 hours: small improvement if data is clean
  10-50 hours: useful domain/accent adaptation
  100+ hours: strong custom ASR system

  For single-speaker TTS:

  10-30 minutes: possible with modern cloning, quality varies
  1-3 hours: usable for experiments
  5-10 hours: much better consistency
  20+ hours: professional-grade potential if recorded well

  For multispeaker TTS:

  many speakers
  many hours per speaker or many total hours
  speaker metadata required

  For voice conversion / cloning:

  a few seconds to minutes may work for zero-shot models
  fine-tuning benefits from cleaner, longer, consented recordings

  Quality matters more than raw duration. One hour of studio-clean, perfectly transcribed speech can beat ten hours of noisy, inconsistent audio.

  Example: Fine-Tuning an ASR Model

  Goal:

  Transcribe support calls with Indian English accents and company-specific terms.

  Dataset:

  audio/call_001.wav
  transcripts/call_001.txt

  Manifest:

  {"audio": "audio/call_001.wav", "text": "I want to renew my vehicle insurance policy."}
  {"audio": "audio/call_002.wav", "text": "Can you explain the zero depreciation add-on?"}

  Steps:

  1. Convert audio to mono 16 kHz WAV.
  2. Segment long calls into 10-30 second utterances.
  3. Clean transcripts.
  4. Fine-tune Whisper or another ASR model.
  5. Evaluate WER on held-out calls.
  6. Add special vocabulary examples.
  7. Test noisy calls, different speakers, phone audio.

  A Hugging Face-style pipeline usually includes:

  from datasets import load_dataset, Audio
  from transformers import WhisperProcessor, WhisperForConditionalGeneration, Seq2SeqTrainer

  Then you:

  load dataset
  resample audio
  convert audio to log-mel features
  tokenize transcript labels
  train
  compute WER
  save checkpoint

  Example: Fine-Tuning a TTS / Voice Model

  Goal:

  Generate narration in one specific speaker’s voice.

  Dataset:

  wavs/0001.wav | This is the first sentence.
  wavs/0002.wav | Welcome to the training module.
  wavs/0003.wav | Please complete the form before Friday.

  Recommended recording rules:

  - Record in the same room.
  - Same mic distance.
  - No background fan/noise.
  - No music.
  - Avoid clipping.
  - Record varied sentence lengths.
  - Include names, numbers, abbreviations, domain terms.
  - Keep emotion consistent unless training emotional control.

  Typical TTS training flow:

  1. Pick model: VITS / XTTS / GlowTTS / NeMo FastPitch etc.
  2. Prepare metadata file.
  3. Normalize text.
  4. Extract mel spectrograms or let framework do it.
  5. Train acoustic model.
  6. Train or use vocoder.
  7. Evaluate generated samples.
  8. Fine-tune more with corrected data.

  Coqui’s docs show this style: choose model, configure dataset path and formatter, initialize audio processor/tokenizer/model, then run trainer on
  GPU.

  Important: Voice Cloning Safety

  Only train or clone:

  - Your own voice.
  - A voice you have explicit written consent to use.
  - Synthetic voices allowed by the provider/license.

  Do not clone public figures, coworkers, customers, or private individuals without consent. For production, add disclosure, logs, abuse monitoring,
  and preferably watermarking or provenance metadata.

  Common Mistakes

  - Fine-tuning before checking whether prompting or retrieval solves the problem.
  - Training on dirty transcripts.
  - Mixing sample rates and microphone qualities.
  - No held-out test set.
  - Overfitting a tiny voice dataset.
  - Measuring only loss, not real audio quality.
  - Ignoring latency.
  - Training TTS with expressive/emotional data but expecting neutral output.
  - Trying to clone a voice from low-quality YouTube/audio-call clips.
  - Forgetting legal consent.

  Recommended Path

  If you want a practical route:

  3. For custom speaking voice: use a consented TTS/voice-cloning system, then fine-tune only if zero-shot quality is not enough.
  4. For model behavior: fine-tune the text/reasoning model, not the voice model, unless the audio itself is the problem.
  5. Build evals before training. Otherwise you will not know whether the fine-tune helped.

• Yes, you should use a hybrid approach:

  1. Use existing tools to get a first pass.
  2. Build a small local review/trimming tool for your own dataset.
  3. Do human approval before using clips for cloning/fine-tuning.

  Automatic tools can help, but they will not trim “exactly Ashwini only” with 100% accuracy, especially from WhatsApp call audio.

  What You Need

  The task is called speaker diarization: finding “who spoke when.” WhisperX describes this as ASR with word-level timestamps and speaker
  diarization, and pyannote is built specifically for identifying/separating speakers in recordings. Sources: WhisperX
  (https://github.com/m-bain/whisperX), pyannote.ai (https://www.pyannote.ai/).

  For your case, the pipeline should be:

  raw WhatsApp call
  -> detect speech
  -> split by speaker
  -> identify which speaker is Ashwini
  -> export only Ashwini segments
  -> transcribe each segment
  -> manually approve/correct
  -> save clean dataset for TTS/voice cloning

  Recommended Tools

  Use these in this order.

  1. Audacity

  Best for manual inspection and exact trimming.

  Use when:

  - You want to listen and manually cut Ashwini’s voice.
  - You want privacy because it runs locally.
  - You want to visually inspect waveform/silence/noise.

  Audacity is free, open-source, and supports editing/exporting audio on Windows/macOS/Linux. Source: Audacity (https://www.audacityteam.org/).

  This is the most reliable option for final cleanup.

  2. WhisperX

  Best developer tool for your case.

  Use it for:

  - transcription
  - word-level timestamps
  - speaker labels
  - rough diarization
  - generating a first-pass CSV/JSON of speaker segments

  WhisperX supports word-level timestamps and speaker diarization through pyannote. It also warns that diarization is not perfect and overlapping
  speech is difficult, which matters for your dataset. Source: WhisperX GitHub (https://github.com/m-bain/whisperX).

  3. pyannote.ai / pyannote.audio

  Best for speaker diarization.

  Use it for:

  - “Speaker 1 / Speaker 2” segmentation
  - speaker identification
  - detecting overlap
  - marking areas needing human attention

  pyannote.ai specifically supports diarization, speaker identification, overlap detection, voice activity detection, and speaker separation.
  Source: pyannote.ai (https://www.pyannote.ai/).

  4. Adobe Podcast Enhance

  Use only for cleaning a copy of the audio, not as your main dataset source.

  It can improve muffled/noisy speech, but for voice cloning you must be careful: enhancement tools can alter the speaker identity. Use it for
  listening/transcription help, but keep the original or lightly cleaned audio for model training. Source: Adobe Enhance Speech
  (https://podcast.adobe.com/enhance).

  5. ElevenLabs Voice Isolator / Cleanvoice / Auphonic

  These can help reduce noise and improve speech clarity. But again: they may change the voice texture. Good for review, not always good for final
  cloning data.

  Should We Build Software?

  Yes, but not a full AI model. Build a dataset cleaning tool.

  For your project, I would build something like:

  audio_cleaner/
    input: audio/wavs/*.wav
    output:
      audio/dataset_clean/wavs/aswini_0001.wav
      audio/dataset_clean/metadata.csv
      audio/dataset_clean/dataset.jsonl

  Features:

  - Run WhisperX/pyannote on each raw call.
  - Label speakers as SPEAKER_00, SPEAKER_01, etc.
  - Let you mark which speaker is Ashwini.
  - Export only Ashwini segments.
  - Reject overlap automatically.
  - Reject clips shorter than 2.5 sec or longer than 10 sec.
  - Add 100-200 ms padding at start/end.
  - Play each clip in a small review UI.
  - Let you mark: keep, reject, needs transcript fix.
  - Save corrected transcript.

  The important part is the human review UI. Fully automatic trimming will poison your dataset.

  Best Practical Workflow

  For your current 136 clips:

  1. Run diarization on the original 14 call WAVs, not only the already segmented clips.
  2. Identify Ashwini’s speaker label per call.
  3. Export Ashwini-only turns.
  4. Discard customer speech.
  5. Discard overlapping speech.
  6. Discard noisy/unclear clips.
  7. Manually correct transcripts.
  8. Keep only the best 30-80 clips first.
  9. Test F5-TTS / XTTS voice cloning.
  10. Only then expand the dataset.

  My Recommendation

  Do not spend too much time on random web portals. Use:

  - WhisperX + pyannote for automatic first pass.
  - Audacity for exact manual correction.
  - A small custom local tool for review/export.

  That gives you control and keeps the dataset structured for TTS training. The target is not “many clips”; the target is clean Ashwini-only clips
  with exact text.
